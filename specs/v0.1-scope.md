# v0.1 scope and implementation handoff

## Goal

v0.1 proves the core promise of DenDenAPI: a consumer can retrieve a small but coherent manga-canon dataset in English or Spanish, view it at a story point, cap spoilers, and inspect official provenance.

v0.1 is a vertical slice, not an attempt to encode the entire One Piece corpus. API capability and dataset coverage are tracked separately.

## In scope

### Foundation

- Stable opaque IDs and stable non-localized slugs.
- Localized names/descriptions with `?lang > Accept-Language > en`.
- `asOfChapter`, `maxChapter` and recursive spoiler-safe projections.
- Official source references and dataset release metadata.
- Validation of interval, identity and evidence invariants.

### Story and publication

- `Saga`, `Arc`, `Chapter`, `Volume` and `VolumeEdition`.
- Chapter-to-arc and chapter-to-volume assignment.
- Derived arc, saga and volume chapter ranges.
- `CoverStory` and `CoverStoryEpisode` for the curated dataset.
- `SBS` as a provenance target attached to a volume; full SBS entry text is excluded.

### World and characters

- `Character`, localized `CharacterName` (`PRIMARY`, `ALIAS`, `EPITHET`), profile facts (gender, birthday, age and height) and historical `CharacterStatusRecord`.
- `Race`, `CharacterRace`, `Location` and character origin/debut references.
- `Organization` with generalized types.
- Historical `OrganizationMembership`, role definitions/assignments, organization relationships, status and locations.
- Historical `Bounty`.
- `DevilFruit` and historical `DevilFruitUser`.
- `CharacterHaki` using the three canonical types, without invented levels.

### Public API slice

- Read-only collection and detail endpoints for the entities above.
- Bounded `include` expansions needed to demonstrate the model.
- Cursor pagination and an explicit filter allowlist.
- Consistent problem response, language headers and cache keys.

## Deferred after v0.1

The concepts below are documented so v0.1 does not block them, but they do not require tables, seed data or endpoints yet.

| Area | Deferred work |
| --- | --- |
| Genealogy | `Family`, detailed `CharacterRelationship`, family/organization links |
| Professions | Localized `Occupation` and historical character occupation assignments |
| Global positions | `WorldTitle`, `CharacterWorldTitle` |
| Combat | `FightingStyle`, `Technique`, advanced Haki techniques |
| Equipment | `Weapon`, grade taxonomy, historical ownership |
| Vessels | `Ship`, ship status, organization/character ship relationships |
| Publication detail | Full `SBSEntry` content and special-chapter numbering |
| Sources | Vivre Card/databook ingestion and conflict precedence |
| Appearance graph | Exhaustive per-chapter character appearances |
| Continuities | Anime, films, games, filler and cross-continuity mappings |
| Discovery | Full-text search, arbitrary graph traversal and complex facets |
| Write workflows | Public mutations, community submissions and moderation UI |

## Explicit non-goals

- Ktor project scaffolding.
- PostgreSQL schema or migrations.
- Hosting, authentication, observability or deployment design.
- Automated scraping from Fandom or other community sites.
- Mirroring copyrighted prose or imagery.
- Completing production seed data for every published chapter.

Those decisions begin only after the domain package is reviewed and frozen.

## Dataset milestone

The first seed must be deliberately small but exercise every v0.1 invariant. It should include:

- at least two sagas and multiple arcs/volumes/chapters;
- one cover story with multiple episodes;
- characters with translated names, alias/epithet and status history;
- an organization hierarchy, an alliance/affiliation and membership role change;
- a historical headquarters or organization status change;
- multiple bounty records for one character;
- at least one Devil Fruit user and each Haki type represented where canonically supported;
- a fact whose story validity predates its reveal, proving `asOfChapter` and `maxChapter` differ;
- manga and SBS provenance examples.

The seed examples must be verified against official sources before publication. Documentation examples are illustrative and are not automatically seed truth.

## Definition of done for domain freeze

- [x] Reviewers agree on entity boundaries and naming.
- [x] Reviewers accept the distinction between validity and availability.
- [x] Organization, Family and WorldTitle remain separate abstractions.
- [x] Locale negotiation and English fallback are accepted.
- [x] v0.1 entities and deferred entities are unambiguous.
- [x] Source authority and copyright boundaries are accepted.
- [x] Open proposals (gender enum, bounty status, mixed-language field fallback) are resolved.
- [x] Representative queries can be answered without adding denormalized source-of-truth fields.

The domain freeze was approved on 2026-09-27. Later semantic changes require explicit approval and an update to the relevant source-of-truth document.

## Implementation sequence after approval

```mermaid
flowchart LR
    A[Approved domain freeze] --> B[Define API contract / OpenAPI]
    B --> C[Design persistence schema]
    C --> D[Implement validation + projections]
    D --> E[Load verified seed dataset]
    E --> F[Contract, temporal and spoiler tests]
    F --> G[Publish v0.1 preview]
```

Recommended vertical order:

1. Chapter/source identity and dataset metadata.
2. Localization resolver.
3. Temporal/spoiler projection engine.
4. Character slice with names and status.
5. Organization memberships, roles and derived values.
6. Remaining v0.1 read models.
7. OpenAPI, fixtures and end-to-end compatibility tests.

## Required test scenarios

Before a public preview, tests must demonstrate:

1. `?lang` overrides `Accept-Language`, then English is used as fallback.
2. IDs and slugs do not change with locale.
3. `asOfChapter` changes historical state independently of `maxChapter`.
4. A late reveal is absent from direct, nested, derived, list and error surfaces.
5. No overlapping single-valued status or primary-name intervals are accepted.
6. Role assignments remain within membership intervals.
7. Direct and effective organization affiliations are not confused.
8. Bounty totals and member counts use only visible active records.
9. Every required fact has resolvable official provenance.
10. Dataset version and maximum ingested chapter are exposed.

## Handoff decision log

The following are frozen unless review changes them:

- manga-first canon with official supplementary provenance;
- complex internal model and simple public projections;
- stable `id` + stable non-localized `slug`;
- generalized `Organization`, not `Crew`;
- historical memberships, roles, status, locations and bounties;
- `Family` and `WorldTitle` are not organizations;
- independent validity and spoiler-availability dimensions;
- language precedence `?lang`, `Accept-Language`, English;
- deterministic field-level locale fallback: exact tag, base language, English;
- `Content-Language` lists every locale actually used by a response;
- character gender values are `MALE`, `FEMALE`, `NON_BINARY`, `UNKNOWN` and `NOT_APPLICABLE`, with absence kept distinct;
- bounty status values are `ACTIVE`, `FROZEN`, `WITHDRAWN` and `UNKNOWN`, and organization totals use only visible `ACTIVE` bounties;
- derived values are not duplicated as authoritative fields;
- no framework or database implementation in this phase.
