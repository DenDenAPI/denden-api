# Specifications

Every feature begins with an approved specification in this directory.

A specification defines its goal, scope, out of scope, requirements, public API contract when applicable, acceptance criteria, and unresolved questions. Keep one feature per file and do not use a specification to introduce unapproved domain, API, architecture, data-model, or major-dependency decisions.

The existing [v0.1 scope and implementation handoff](v0.1-scope.md) defines the product boundary. Smaller implementation specifications should reference it rather than silently expanding it.
